# 결산 리포트 기능 명세서

작성일: 2026년 11월 7일 한국시간  
버전: 1.1  
저장소: https://github.com/geonjuring/AX-Hackathon  
구현 기준: 기존 기능에서 웹 예약 UI를 임시 제거하고 테스트를 tests 폴더로 분리한 버전

## 1. 서비스 개요

결산 리포트는 로컬 CSV의 생산실적, LOT 연결, RPM, 생산일보 인원 및 전력 사용량을 결합하여 일별·주별·월별 지표와 시각화를 제공하는 Streamlit 웹 애플리케이션이다. 조회 조건을 바꾸면 지표를 다시 계산하며, HTML·CSV 다운로드와 서버 저장을 지원한다. 팀 서버 이전 준비를 위해 웹 예약 UI는 임시 제거했다.

실제 데이터는 공개 저장소에 포함하지 않는다. 사용 환경에 데이터를 별도로 배치해야 한다. MES 실시간 연결이나 MES 결과 직접 조회는 사용하지 않는다.

## 2. 조회 조건과 집계 범위

| 기능 ID | 기능 | 입력 및 동작 |
|---|---|---|
| Q01 | 집계 단위 선택 | 일별·주별·월별. 내부 계산 코드는 일간·주간·월간 값을 사용한다. |
| Q02 | 일별 기간 선택 | 기준일을 선택하여 당일 지표를 조회한다. |
| Q03 | 주별 기간 선택 | 기준 연월과 월내 주차를 선택한다. 1~7일, 8~14일, 15~21일, 22~28일, 29~말일로 구분한다. |
| Q04 | 월별 기간 선택 | 기준 연월을 선택한다. 기준 연월 목록은 생산실적의 최초·최종 월 범위로 구성한다. |
| Q05 | 공장 선택 | 전체 공장·1공장·2공장. 1공장은 01~08호기, 2공장은 11~19호기이다. |
| Q06 | 생산 라인 선택 | 통합 또는 개별 호기를 선택한다. 통합은 선택한 공장의 전체 호기를 뜻한다. |
| Q07 | 근무조 선택 | 전체·A조·B조. 생산량·LOT·인당 생산량은 선택 조 기준으로 계산한다. |
| Q08 | 조회 조건 저장 | 팀 서버 이전 전 임시 제거. 화면에서는 예약 조회 조건을 저장하지 않는다. |
| Q09 | 원본 새로 읽기 | Streamlit 데이터 캐시를 비우고 재실행한다. 파일 기반 전력·RPM 캐시는 원본 수정 시각과 크기가 바뀌면 다시 생성한다. |

공장 전체 전력량은 공장·라인 필터와 무관하게 유지한다. 압출기 전력량과 호기별 전력·가동률은 선택 호기 기준이다. A/B조 비교 카드는 선택한 라인에서 두 조를 모두 비교한다. 전력과 가동률을 A/B조에 나누어 배정하지 않는다.

## 3. 주요 지표

| 지표 | 계산 정의 | 표시 단위 |
|---|---|---|
| 기간 생산량 | 선택 기간·라인·조의 양수 생산실적 `pr_qty` 합계 | kg |
| A조·B조 생산량 | 선택 기간·라인의 `jo=A`, `jo=B` 생산량 합계 | kg |
| 평균 LOT SIZE | 기간 생산량 ÷ 날짜별 라인·LOT 수의 합계 | kg/LOT |
| 통합 LOT SIZE | 기간 생산량 ÷ 날짜별 통합 그룹·단독 LOT 묶음 수의 합계 | kg/LOT |
| 가동률 | 가동 분 합계 ÷ 기준 분 합계 × 100 | % |
| 금월 총생산량 | 일별 조회는 해당 월 1일~기준일의 선택 실적 합계. 주별·월별 조회는 해당 월의 확보된 일간 실적 합계 | kg |
| 가동일 | 일별 조회는 월초~기준일, 주별·월별 조회는 선택 기간에서 선택 생산량이 양수인 날짜 수 | 일 |
| 일평균 | 일별 조회는 금월 총생산량 ÷ 금월 가동일. 주별·월별 조회는 기간 생산량 ÷ 기간 가동일 | kg/일 |
| 인당 생산량 | 선택 생산량 ÷ 생산일보에서 계산한 적용인원 합계 | kg/명·교대 |
| 전체 전력량 | 공용 설비를 포함한 전체 소비 센서 사용량. 청구 자료 적용 여부에 따라 아래 전력 기준을 사용 | kWh |
| 압출기 전력량 | 선택 호기의 압출기 센서 사용량 합계 | kWh |

분모가 0이거나 필요한 값이 확보되지 않으면 미산출로 처리한다. 통합 LOT SIZE의 표기 단위는 kg/LOT이지만, 계산 분모는 연결표 기준 통합 그룹과 단독 LOT를 합친 묶음 수이다.

### 3.1 LOT 연결

`p_grplot_list.csv`의 `lot_no → grp_lot_no`를 기준으로 통합 그룹을 구성한다. 연결표에 없는 LOT는 단독 LOT로 처리한다. 단독 LOT는 라인·LOT 기준으로 구분한다. 스케줄 순서나 GRADE·COLOR의 연속성으로 추가 그룹을 추정하지 않는다.

한 그룹의 라인·GRADE·COLOR가 달라도 연결표의 동일 그룹은 유지한다. 서로 다른 그룹으로 중복 연결된 LOT는 오류로 처리한다. 주별·월별 LOT 분모는 기간 전체 LOT 번호를 한 번만 세는 방식이 아니라 날짜별 건수를 합산한다.

### 3.2 가동률

1. `HMI_feeder_list.csv`를 생산일 `p_date`, 호기 `line`, `times`의 시간대별로 집계한다.
2. RPM `mval02 > 250`인 원본 행 수를 가동 분으로 사용하고, 시간당 최대 60분으로 제한한다.
3. 가동 분이 양수인 호기·날짜만 계산 대상에 포함한다.
4. 대상 호기·날짜 1건당 기준 분은 1,440분이다. 포함한 호기의 당일 정지·기록 누락 시간은 분모에 남긴다.
5. 주별·월별은 가동 분과 기준 분을 각각 합산하여 비율을 계산한다. 일별 비율을 단순 평균하지 않는다.

정확히 RPM 250인 기록은 가동에 포함하지 않는다. 현재 구현에는 과거 논의한 ‘RPM 250 미만 연속 5분’ 조건을 적용하지 않는다. 가동 분은 원본 행 수를 분으로 환산한 값이며, 기록 확보율은 `input_dt`를 분 단위로 중복 제거하여 별도로 계산한다.

가동 이력이 없는 호기·날짜는 제외한다. 기록이 없는 경우를 실제 정지로 확정하지 않으며, 관련 상태와 누락 분은 데이터·상세 내역에 보관한다. 화면은 가동 호기 목록과 CSV 다운로드를 제공한다.

### 3.3 적용인원과 근무조

- 적용인원은 원칙적으로 `tot_cnt - abs_cnt`이다. 원본 `cur_cnt`와 CSV를 수정하지 않는다.
- 총원·결원은 비어 있지 않은 0 이상 정수여야 하며 결원은 총원을 초과할 수 없다.
- 결원 0인데 현원과 총원이 서로 다르면 확인 대상으로 두고 자동 적용하지 않는다. 결원이 있으면 유효한 총원−결원을 적용한다.
- 2공장 D조→A조, E조→B조를 기본 통일한다. 같은 날짜·공장·주야간의 생산실적 조가 하나로 확인되면 이를 우선하여 반대 조 기록도 보정한다. 생산실적이 없거나 조가 모호하면 조 연결을 보류한다.
- 선택 공장의 주·야간 인원 기록이 누락·중복되거나 유효하지 않으면 인당 생산량을 미산출한다.
- 인당 생산량은 공장 전체 라인을 선택했을 때 자동 적용한다. 호기별 실제 인원 배치 근거가 없어 개별 호기에 공장 인원을 임의 배분하지 않는다.
- 주별·월별은 선택 생산량이 양수인 날짜의 적용인원을 합산한다. 필요한 생산일 중 인원 미확인 날짜가 있으면 기간 인당 생산량도 미산출한다.

분모는 명·교대의 누적값이며, 기간 중복을 제거한 실인원이나 근태로 검증한 실제 출근 인원이 아니다. 웹페이지에는 인원 직접 입력 기능이 없다. 계산 함수에는 별도 호출용 수동 인원 매개변수가 남아 있다.

날짜별 A/B조 주야간은 생산실적 `juya` 1=주간, 2=야간으로 표시한다. 주간은 08:30~20:30, 야간은 20:30~다음 날 08:30이다. 조회 호기나 선택 조만으로 추정하지 않고 해당 공장의 생산실적에서 확인한다.

### 3.4 전력량과 청구 기준

| 구분 | 집계 방식 |
|---|---|
| 청구 적용 월 | 월 청구량 ÷ 해당 월 달력일 소비 센서 합계를 계수로 사용하여 일자·센서별 사용량에 비례 배분한다. |
| 청구 미적용 월 | DB 센서의 생산일 08:30~다음 날 08:30 사용량 합계를 사용한다. |
| 청구 배분 시각 | 달력일 00:00~다음 날 00:00 |
| 공장 전체 범위 | 소비 센서 전체. 태양광 센서 217은 제외한다. |
| 호기별 범위 | 압출기 + 히터·부속. 8호기는 압출기 403, 히터 512, 휴게실 510을 포함한다. 공용 설비를 호기에 임의 배분하지 않는다. |

현재 청구 배분 코드는 2026년 1~10월만 적용 대상으로 제한한다. 청구 자료가 없거나 배분용 월간 원본 조건을 충족하지 못하면 센서 기준을 유지한다. 배분은 0.1 kWh 단위 잔여량을 조정하여 월 합계를 청구량에 맞춘다.

청구 기준은 결측 구간만 채우는 방식이 아니라 관측 사용 패턴에 따라 월 사용량을 조정하는 추정 배분이다. 원본을 덮어쓰지 않으며, 개별 날짜·설비의 실제 사용량을 복원한 값으로 해석하지 않는다. DB 센서 기준에서 일부 15분 구간이 없으면 확보한 값의 잠정 합계가 남을 수 있다.

## 4. 화면과 시각화

메인 화면에는 주요 지표 카드와 가동 호기 목록, 날짜별 A/B조 주야간 확인 내역을 표시한다. 메인 탭은 생산 현황, 기간 리포트, 통합 LOT 검토, 계산 기준이다.

시각화 집계 단위는 상단 리포트 집계와 별도로 전환할 수 있다. 일별은 선택 월의 날짜별, 주별은 선택 월의 고정 주차별, 월별은 선택 연도의 확보된 월별로 비교한다. 시각화 전환만으로 상단 지표의 조회 조건을 바꾸지 않는다.

| 기능 ID | 시각화 탭 | 동작 |
|---|---|---|
| V01 | 생산량 | A/B조는 나란한 막대, 전체는 꺾은선. 조 선택 시 선택 조 막대만 표시한다. |
| V02 | 호기별 가동률 | 비교 기간을 선택하고 호기별 가로 막대를 표시한다. 호기 번호 오름차순, 막대 끝에 % 표시. 미산출 호기는 0%와 구분한다. |
| V03 | LOT SIZE | 평균·통합 LOT SIZE를 나란한 막대로 비교한다. 민트·파란색으로 구분하며 툴팁 단위는 kg/LOT이다. |
| V04 | 전력량 | 위에 공장 전체 사용량 추이, 아래에 선택 기간의 호기별 가로 누적 막대를 표시한다. 압출기와 히터·부속을 구분하고 합계 kWh를 표시한다. |
| V05 | 전력 효율 | 호기별 전력량 ÷ 해당 호기 전체 조 생산량(톤)을 가로 막대로 표시한다. 호기 번호순이며 막대 끝과 툴팁에 kWh/톤을 표시한다. |
| V06 | 생산량·전력 효율 | 호기별 생산량은 민트색 막대·왼쪽 축(톤), 톤당 전력량은 주황색 꺾은선·오른쪽 축(kWh/톤)으로 함께 표시한다. |

전력 효율의 분모는 근무조 필터와 무관하게 해당 호기의 전체 조 생산량이다. 생산량이 0이거나 필요한 전력값이 없으면 효율을 산출하지 않는다. 제품·LOT 규모·가동 조건이 다르면 효율 차이를 설비 성능 차이로 단정하지 않는다. 청구 기준 전력과 생산실적은 날짜 경계가 달라 일별 효율 비교 시 주의가 필요하다.

차트는 툴팁으로 상세 수치를 제공한다. 월별 시각화는 `build_chart_history()`에서 필요한 생산량·LOT·전력·가동 기록만 일괄 집계하고 캐시를 재사용한다. 그래프 생성 때문에 날짜별 전체 리포트와 인원 계산을 반복하지 않는다.

## 5. 리포트와 파일 출력

| 기능 ID | 기능 | 출력 |
|---|---|---|
| R01 | 기간 리포트 | 선택 실적·생산량·가동일·가동률·인원 설명과 인원 조 연결 근거 |
| R02 | 통합 LOT 검토 | 연결표 기준 통합 그룹·단독 LOT의 수량, 라인, GRADE, COLOR |
| R03 | 화면 CSV 다운로드 | 생산 추이, 라인별 생산, LOT 그룹, 가동 호기 목록, 주야간, 인원 조 연결 근거 |
| R04 | HTML 다운로드 | 인쇄 가능한 리포트 HTML. PDF는 브라우저 인쇄 기능으로 저장하며 서버 PDF 변환 기능은 없음 |
| R05 | 서버 저장 | HTML·지표 JSON·라인/LOT/가동 호기/근무조/인원 연결 CSV와 일간 원장·주차별 합계 CSV |

서버 저장 기본 경로는 프로젝트의 `reports/` 아래이다. 일별은 날짜, 주별·월별은 집계 단위와 시작일_종료일 폴더를 사용한다. 청구 배분 적용과 선택 조에 따라 하위 폴더가 추가된다. 같은 조건으로 저장하면 해당 경로의 파일을 갱신한다.

월내 일간 원장과 주차별 합계는 리포트 파일에 포함되지만, 메인 화면에 별도 ‘일간→주간→월간 합계 검증’ 영역은 제공하지 않는다.

## 6. 명령어 생성과 예약 기능 상태

웹페이지의 예약 조회 조건 저장, 실행 시각 입력, 예약 등록·변경·해제 버튼과 예약 안내를 임시 제거했다. 팀 서버의 설치 경로·시간대·cron 권한을 확인한 후 다시 연결할 수 있다. 화면의 수동 HTML·CSV 다운로드와 서버 저장은 유지한다.

`production_report.py`의 CLI와 `configure_schedule()` 함수는 복원용으로 유지한다. CLI는 `--date YYYY-MM-DD/yesterday/latest`, `--period 일간/주간/월간`, `--energy-basis 청구기준/실측`을 지원한다. 저장된 `report_settings.json`이 있으면 CLI는 계속 해당 조건을 참조한다.

코드나 테스트를 가져오는 것만으로 cron이 등록되지는 않는다. 다른 설치 위치에서 예약 함수를 다시 사용할 경우 `/data/hackathon` 고정 경로를 수정해야 한다. 예약 함수는 Linux·UTC 서버와 사용자 crontab 권한을 전제로 하며, 관련 동작은 테스트에서 모의 호출로 검증한다. 웹 UI 제거만으로 기존 시스템 cron 작업이 해제되지는 않으므로 이전 서버에서 앱 작업이 남아 있는지 별도 확인한다.

## 7. 입력 데이터 요구사항

기본 데이터 경로는 프로젝트의 `v1/해커톤_업로드_2026`이며, 현재 환경변수나 `.env`로 자동 변경하지 않는다.

| 상대 파일 경로 | 사용 컬럼과 용도 |
|---|---|
| `03_에이전트용/p_prod_result.csv` | `lot_no`, `p_date`, `line`, `jo`, `juya`, `pr_qty`: 생산실적 |
| `03_에이전트용/p_prod_plan.csv` | `lot_no`, `line`, `grade`, `color`: LOT 메타데이터 연결 |

| `01_분석용/p_prod_rpt.csv` | `p_date`, `fac_cd`, `juya`, `jo`, `tot_cnt`, `cur_cnt`, `abs_cnt`: 적용인원과 조 연결 |

생산 날짜는 YYYY.MM.DD, 전력 시각은 타임스탬프 형식을 전제로 파싱한다. 호기·LOT는 문자열로 취급한다. 급여·직원명부는 입력으로 사용하지 않는다. 정제 데이터 경로로의 전환은 이 버전에 포함하지 않는다.

## 9. 오류 처리와 데이터 품질

- 필수 파일 읽기 오류·일부 데이터 유효성 오류는 화면 오류로 표시하고 처리를 중단한다.
- 생산 날짜·수량의 파싱 실패, 수량 음수, 충돌하는 LOT 연결은 오류로 처리한다.
- 동일 센서의 15분 시각 중복과 잘못된 전력 날짜를 검사한다.
- 인원 누락·중복·모순을 임의 인원으로 보완하지 않는다.
- 누락 RPM을 가동 분으로 채우거나 실제 정지로 확정하지 않는다.
- 전력 결측을 임의의 전후 평균으로 채우는 기능은 없다. 청구 배분과 원본 센서 합계는 구분한다.
- 메인 상단의 반복 상태 알림은 제거되어 있다. 일부 미산출 안내, 상세 근거, 지표 상태와 다운로드 HTML의 주의 문구는 남아 있다.

## 10. 실행과 운영 범위

Python 3.12와 Linux 서버 기준의 구현이다. `pip install -r requirements.txt` 후 `streamlit run app.py`로 실행한다. 파일 기반 캐시는 `.report_cache/`에 저장한다. 원본 새로 읽기는 공유 Streamlit 데이터 캐시에 영향을 준다. 웹 조회 조건 저장 UI는 임시 제거했으며 `report_settings.json`은 CLI에서만 참조한다.

앱 자체의 로그인·역할별 권한 관리·다중 사용자별 예약 분리는 구현하지 않는다. 공개 코드 등록이 실제 데이터 공개나 웹 호스팅 배포를 자동으로 수행하지는 않는다. GitHub Actions CI도 현재 코드 기준에는 포함되지 않는다.

## 11. 검증 기준

기능 확인 시 동일한 데이터와 조회 조건을 사용한다.

| 검증 항목 | 기대 결과 |
|---|---|
| 일별·주별·월별 조회 | 각각 기준일, 연월+주차, 연월 선택에 맞는 범위를 집계 |
| 생산량 | 선택 기간·라인·조 원본 합계와 일치 |
| LOT | 미등록 LOT가 단독 처리되고 기간 분모가 날짜별 건수 합계와 일치 |
| 가동률 | 가동 이력 있는 호기·날짜만 기준 분에 포함, 주·월 분자·분모 보존 |
| 인원 | 총원−결원 및 실적 조 보정 적용, 미확인 기록은 미산출 |
| 청구 전력 | 적용 가능한 월의 0.1 kWh 단위 배분 합계가 청구량과 일치 |
| 호기별 효율 | 전체 조 생산량 사용, 생산량 0·전력값 없음에서 비율 미산출 |
| 그래프 | 호기 번호 오름차순, 각 축·툴팁 단위 구분, 시각화 단위 변경 시 상단 조회 조건 유지 |
| 출력·예약 | CSV/HTML 생성, cron의 다른 작업 보존과 한국시간 변환 확인 |

테스트 실행 명령은 `python -m unittest discover -s tests -t . -p 'test_*.py'`이다. 테스트 파일 5개는 tests 패키지에 배치하며, 기존 검증 항목은 36개이다. 원본 데이터가 바뀌거나 계산식을 바꾸면 동일 조건으로 재검증해야 한다.
